Lab 01: Deploy Developer SKU APIM

Create the gateway and management environment that every later lab reuses.

Azure portalL300~15 min active + provisioning

Scenario and Objectives

You need a disposable environment for publishing a Catalog API. Deploy it before the session so provisioning does not block the later labs.

  • Create a dedicated workshop resource group.
  • Deploy a classic Developer-tier APIM instance.
  • Verify readiness and record its actual gateway URL.

Prerequisites and Names

  • Use a non-production Azure subscription with permission to create the resources and register required providers, or have an administrator register them first.
  • Choose an approved APIM region and a short lowercase alphanumeric suffix. Keep the same values across all labs.
  • Review the common prework and complete this deployment before Lab 02.

Important: Developer is a paid, non-production tier with no SLA. Do not select Basic v2 just because the portal recommends it for evaluation; these labs intentionally use Developer.

Build

Step 1: Create the Instance

  1. Sign in to the Azure portal.
  2. Select Create a resource, then search for API Management.
  3. Select Create to open the creation form.
  4. Select your workshop subscription on Basics.
  5. For Resource group, select Create new and enter rg-apim-workshop-<suffix>.
  6. Enter the unique Resource name, your approved Region, an organization name, and your own Administrator email. Do not share the email or subscription details in screenshots.
  7. Select Developer for Pricing tier and keep one unit.
  8. Leave optional add-in monitoring services unselected for this lab. Keep public networking; do not configure a virtual network or custom domain.
  9. Select Review + create, inspect the tier and estimated charges, then select Create.

Expected result: a deployment starts in your dedicated group. If you already completed prework, inspect the existing instance rather than creating a second one.

Step 2: Wait for Readiness

  1. Open the deployment and inspect its status. Continue concept reading while it runs; do not launch a duplicate deployment.
  2. After deployment succeeds, open the APIM resource and wait until its provisioning status is Succeeded / online rather than activating or updating.
  3. On Overview, copy the Gateway URL to your private workshop notes.
  4. Open APIs > APIs and confirm that the API management surface loads.
Learn more: Current creation steps and tier capabilities. Verified on 2026-10-16.

Test and Verify

  • The deployment succeeded in the dedicated resource group.
  • The pricing tier is Developer, not a v2 or Consumption tier.
  • The resource is ready and its API list opens.
  • You recorded the HTTPS gateway endpoint without credentials.

A 404 from the gateway root is not a failed deployment: you have not published a root operation. Readiness here is the resource status and management access; test actual API calls in Lab 02.

Troubleshooting

SymptomCheck
Name unavailableChoose another suffix before deployment; do not reuse another attendee's service.
Policy or permission denialRead the deployment error and ask the subscription administrator to approve the region, tier, or provider. Do not switch to a different tier silently.
Provisioning still runningInspect deployment operations. Wait or use a clearly identified demonstration environment; do not mark the personal lab complete.
Wrong subscriptionCheck the portal directory and subscription filter before creating more resources.

Cleanup and References

Continuing? Keep this instance for Labs 02-05. Charges continue while resources exist.

Stopping permanently? Open Resource groups, select your exact dedicated workshop group, inspect all its resources, and choose Delete resource group. Enter its name and confirm only if every resource belongs to this workshop. Verify the group is removed. The final cleanup checklist covers the complete environment.
