Lab 04: Publish the Developer Portal

Offer your APIs as a product and verify the published consumer experience with the right subscription scope.

Azure portal + developer portalL300~25 min

Scenario and Objectives

A developer should discover and call your APIs without asking you for an administrator key. Publish a small product and walk through its consumer journey.

  • Create a protected product with both imported APIs.
  • Customize and publish portal content.
  • Request a product-scoped subscription as a consumer.
  • Call the Catalog API and resolve browser CORS issues.
Related topic: Products and Developer Experience.

Prerequisites and Names

  • Complete Labs 01-03 and confirm both APIs work through APIM.
  • Use a private browser window for the consumer, separate from the administrative editor.
  • Have an email account you control for developer signup and verification. Never publish its details.

Build

Step 1: Publish a Product

  1. Open APIM > Products > + Add.
  2. Enter Catalog Workshop as Display name and a short description.
  3. Set State to Published.
  4. Enable Requires subscription.
  5. Leave Requires approval unselected for this disposable lab so requests are automatically approved.
  6. Select Catalog API and Availability API in APIs, then select Create.
  7. Open the product's Access control and confirm the Developers group can see it. Add that group if absent.

Expected result: a published, subscription-protected product contains both APIs. Do not rely on Starter or Unlimited sample products.

Learn more: Create, publish, and expose a product.

Step 2: Customize and Publish the Portal

  1. Open Developer portal > Portal overview.
  2. Select Developer portal to open its administrative editor.
  3. On the home page, edit a text widget to describe the Catalog Workshop APIs.
  4. Select Save.
  5. Select Publish site and wait for publication to finish. Alternatively use Publish on the Azure portal's Portal overview.
  6. Return to Portal overview and inspect the Enable CORS status.
  7. If absent, select Enable CORS to configure access from the developer portal. Do not add competing CORS policies at several scopes.

Expected result: portal publication completes and CORS includes the published developer portal origin. Existing API policies retain their <base /> inheritance.

Learn more: Customize and publish and developer portal CORS.

Step 3: Subscribe as a Consumer

  1. Open the published portal URL in a private window, not the editor.
  2. Select Sign up and register with your own details, then complete email verification if requested.
  3. Sign in and select Products.
  4. Open Catalog Workshop.
  5. Enter Catalog Consumer as the subscription name and subscribe.
  6. Open your profile and confirm the subscription is active.

If signup email is delayed, inspect the user in APIM > Users and resolve account activation with the administrator. An administrator can create a product-scoped subscription assigned to the registered user under Subscriptions; do not substitute the built-in all-access subscription or claim the email signup path succeeded.

Important: keep subscription keys in the private browser or an approved local secret store. Do not paste them into source code, shared notes, screenshots, or public test URLs.

Test and Verify

  1. In the published portal, open APIs > Catalog API.
  2. Select the list operation and open its interactive test console.
  3. Select the Catalog Consumer subscription key, then send the request.
  4. Inspect the 200 response and Notebook/Pen payload.
  5. Remove the subscription key from the request and send again, using a fresh console request if needed.
  • The published home page contains your saved text.
  • The signed-in consumer sees Catalog Workshop and both APIs.
  • The active subscription is product-scoped, not all-access.
  • The Catalog call succeeds with the consumer key and fails with 401 without it.
  • There is no browser CORS error.

The Azure portal administrator test console is not a replacement for this consumer test. Check the subscription-scope caveat before adding any product-level policy.

Troubleshooting

SymptomCheck
Product invisibleConfirm Published state, API association, Developers group access, and consumer sign-in.
Old portal contentSave, publish, wait for completion, and refresh the published URL rather than the editor.
Subscription pendingApprove it in APIM or turn off approval intentionally for this lab; verify Active status.
Browser CORS errorCheck the exact portal origin and global CORS policy. Preserve inheritance; do not put the only CORS policy at product scope.
401 with a keyConfirm the subscription is active, scoped to the correct product, and includes this API. Rotate any accidentally exposed key.

Cleanup and References

Keep the environment for Lab 05. The portal and its API backends remain reachable until removed; ongoing resource costs still apply.

If stopping here, remove consumer subscriptions and users you created, then use the final cleanup for your dedicated resource group. Do not remove pre-existing accounts from a shared APIM service.
