Lab 02: Import a .NET 10 API

Publish the read-only Catalog API through APIM and prove that your gateway policy executed.

VS Code + portalL300~40 min

Scenario and Objectives

You own a small Catalog API and want a stable gateway endpoint for consumers. Use synthetic data so you can focus on the contract and request path.

  • Export OpenAPI 3.0 from .NET 10.
  • Deploy a reachable App Service backend.
  • Import operations and configure an API-scoped outbound policy.
  • Verify payloads, denied calls, and request stages.
Related topics: API Design and Import and Policies and Transformation.

Build

Step 1: Run the Supplied API

  1. Open a PowerShell terminal at the repository root.
  2. Run the following commands.
PowerShell - repository root
Set-Location .\samples\CatalogApi
dotnet build
dotnet run --urls http://localhost:5050

Expected result: the build succeeds and the console reports a listener on port 5050. Keep this terminal running.

  1. Open samples\CatalogApi\Program.cs and inspect the explicit version selection:
builder.Services.AddOpenApi(options =>
    options.OpenApiVersion = OpenApiSpecVersion.OpenApi3_0);

Review CatalogApi.http for the list, lookup, missing-product, and OpenAPI requests. The API has no database and makes no persistent changes.

Step 2: Save and Inspect the Contract

  1. Open a second PowerShell terminal in samples\CatalogApi.
  2. Export the definition and inspect its version and paths.
Invoke-WebRequest http://localhost:5050/openapi/v1.json -OutFile .\catalog.openapi.json
$definition = Get-Content .\catalog.openapi.json -Raw | ConvertFrom-Json
$definition.openapi
if ($definition.openapi -eq "3.0.4") {
    $definition.openapi = "3.0.3"
    $definition | ConvertTo-Json -Depth 100 | Set-Content .\catalog.openapi.json -Encoding utf8
}
if ($definition.openapi -notmatch '^3\.0\.[0-3]$') {
    throw "Expected an APIM-compatible OpenAPI 3.0.0-3.0.3 document. Inspect the generator configuration."
}
$definition.paths.PSObject.Properties.Name
Invoke-RestMethod http://localhost:5050/products

Expected result: an exported OpenAPI document between 3.0.0 and 3.0.3, paths /products and /products/{id}, and two products: Notebook and Pen.

Compatibility note: the supplied current generator emits 3.0.4, while APIM's documented 3.0 support currently stops at 3.0.3. The export above normalizes only that patch-level marker within the same 3.0 format. The OpenAPI specification states patch versions share the same feature set. This is not a conversion from 3.1: never relabel a 3.1 document, whose schema semantics differ.
Learn more: APIM-supported OpenAPI versions. The OpenAPI versioning specification explains patch-level compatibility.

Step 3: Deploy to App Service

  1. Stop the local API using Ctrl+C in its terminal after exporting the file.
  2. Set the placeholders below to your workshop values in the second terminal.
  3. Sign in and confirm the selected subscription before deployment.
PowerShell - samples\CatalogApi
$resourceGroup = "rg-apim-workshop-<suffix>"
$appName = "catalog-workshop-<suffix>"
$region = "<approved-region>"
az login
az account show --query "{name:name}" --output table
az webapp up --name $appName --resource-group $resourceGroup --location $region --os-type Windows --runtime "DOTNET:10" --sku F1
if ($LASTEXITCODE -ne 0) { throw "App Service deployment failed. Inspect the Azure CLI error before continuing." }
$hostName = az webapp show --name $appName --resource-group $resourceGroup --query defaultHostName --output tsv
if ($LASTEXITCODE -ne 0) { throw "Could not read the deployed hostname." }
$backendUrl = "https://$hostName"
Invoke-RestMethod "$backendUrl/products"

Expected result: the deployed HTTPS endpoint returns the same two products. Read the actual hostname from Azure; do not assume its shape. If F1 is unavailable, resolve subscription quota/region restrictions first; do not accept a paid plan without reviewing its price.

OpenAPI is exposed locally in Development only. You already saved the file, so do not enable Development on the deployed app just to import it.

Learn more: App Service CLI deployment and OpenAPI generation.

Step 4: Import Into APIM

  1. Open your APIM instance in the Azure portal.
  2. Select APIs > APIs > + Add API.
  3. Select OpenAPI under Create from definition.
  4. Browse to your saved catalog.openapi.json.
  5. Set Display name to Catalog API and API URL suffix to catalog.
  6. Select Create.
  7. Open the imported API's Settings tab.
  8. Set Web service URL to the HTTPS $backendUrl value, with no /products suffix.
  9. Confirm Subscription required is selected, then save.

Expected result: the frontend has two GET operations and routes /catalog/products to the backend's /products.

Step 5: Add an Outbound Header

  1. Select Design > All operations for Catalog API.
  2. Open the policy code editor using the </> icon.
  3. Add the following inside the existing <outbound> section after its <base />. Preserve all other sections.
XML fragment - inside outbound
<set-header name="X-Workshop" exists-action="override">
    <value>apim-catalog</value>
</set-header>
  1. Save the policy and wait for configuration propagation before testing.
Learn more: OpenAPI import, import restrictions, and policy editing and inheritance.

Test and Verify

  1. Select Catalog API > Test and the ListProducts operation (or the corresponding GET /products operation).
  2. Select Send.
  3. Inspect the response body and headers.
  4. Select the product lookup operation and test ID 1, then 999.
  5. For the list operation, select Trace and inspect Inbound, Backend, and Outbound on the response's Trace tab. Do not copy or share trace credentials.
  • The list call returns 200 and exactly two products.
  • ID 1 returns Notebook; ID 999 returns 404.
  • The gateway response includes X-Workshop: apim-catalog.
  • The trace backend URL uses App Service, not localhost.

To verify subscription enforcement independently, open the gateway URL below in a private browser window with no headers or query credentials:

https://<apim-gateway-host>/catalog/products

Expected result: 401 for a missing subscription key. If it succeeds, inspect Subscription required and remove any open-product association. Use a product-scoped consumer key in Lab 04 rather than exporting the administrator's all-access key.

Learn more: Portal tracing and subscription checks.

Troubleshooting

SymptomCheck
SDK or package errorRun dotnet --list-sdks; install .NET 10 and confirm NuGet access.
Local definition returns 404Run with the Development launch profile, not a Production environment, and use port 5050.
App Service deployment failsInspect the CLI error, subscription permissions, available Windows .NET runtimes, and F1 quota. Stop before importing a nonworking backend.
Gateway returns 500/502/404Call the direct backend first; check Web service URL, path suffix, and trace routing.
Header absentCheck API-level All operations outbound policy, inherited policy order, and propagation.

Cleanup and References

Keep APIM, App Service, and catalog.openapi.json for later labs. Stop the local process when not needed. Hosting charges and quotas remain relevant even if no requests are sent.

If ending here, follow the final cleanup for the dedicated group. Deleting only the web app can leave its App Service plan behind.
