Lab 03: Import Azure Functions

Add an HTTP-triggered function behind the same gateway, then protect it against request bursts.

Azure portalL300~25 min

Scenario and Objectives

Your Catalog API needs a complementary function endpoint. Import a prepared function instead of manually copying its URL and credential into every consumer.

  • Import an HTTP-triggered function from its Azure resource.
  • Inspect credential references without disclosing secret values.
  • Apply an API-scoped rate-limit policy.
  • Observe 200, missing-key 401, and throttled 429 responses.
Related topics: API Design and Import and Security and Access Control.

Prerequisites and Names

  • Complete Labs 01-02.
  • Prepare a Function App using the Function prework. It must be in the same subscription, expose an HTTP GET trigger with Function authorization, and be reachable from APIM.
  • Confirm the function returns 200 using its authorized test workflow before importing. Creating and deploying the Function App is prework, not part of this 25-minute lab.

Build

Step 1: Import the Resource

  1. Open APIM > APIs > APIs.
  2. Select + Add API > Function App under Create from Azure resource.
  3. Select Browse and select your prepared Function App.
  4. Select its Availability function.
  5. Use the Full view to set Display name to Availability API and API URL suffix to availability.
  6. Select Create.
  7. On the imported API's Settings tab, confirm Subscription required is selected and save any change.

Expected result: the imported GET operation appears. Keep the route created by import; do not guess the gateway path from the function name.

Step 2: Inspect the Backend Reference

  1. Open APIM > APIs > Named values.
  2. Find the entry named after your Function App with a -key suffix. Do not reveal its value.
  3. Open the Function App > Functions > App keys and confirm a host key named apim-<your-apim-service-name> exists without copying it.
  4. Return to APIM and inspect the imported backend and its credential reference. Confirm the function key is supplied to the backend rather than requested from the API consumer.

Expected result: APIM holds a named-value reference for its backend key. Key rotation is a separate operation: the Function key and APIM named value do not automatically synchronize.

Step 3: Apply a Rate Limit

  1. Select Availability API > Design > All operations.
  2. Open the policy code editor.
  3. Insert this fragment inside <inbound>, after <base />. Preserve existing import-generated settings and all other sections.
XML fragment - inside inbound
<rate-limit-by-key calls="3" renewal-period="30"
    counter-key='@(context.Subscription.Id + ":availability")' />
  1. Save the policy and allow configuration to propagate.

This API requires a subscription, so the expression keys the counter by the authenticated APIM subscription. Keep Subscription required enabled.

Learn more: Function import and generated credentials and rate-limit-by-key reference. Verified on 2026-10-16.

Test and Verify

  1. Open Availability API > Test and choose its GET operation.
  2. If the prepared template accepts a name query parameter, set it to Catalog.
  3. Select Send and inspect the first successful response.
  4. Send a short burst of requests using the same subscription, without modifying any key.
  5. Wait beyond the 30-second renewal window, then send again.
  6. Copy only the operation URL, without keys, into a private browser window to verify a missing subscription key is rejected.
  • A valid call returns 200 with the prepared function's expected response.
  • A burst produces 429 Too Many Requests.
  • A call succeeds again after the renewal window.
  • A request without an APIM subscription key returns 401.
  • The consumer does not need the Function host key.
Note: distributed rate limiting is approximate. Do not require rejection on precisely the fourth request. If repeated rapid calls never return 429, inspect scope, effective policy, counter key, and subscription context.

Troubleshooting

SymptomCheck
No function available for importCheck subscription, HTTP trigger, deployed function discovery, and Anonymous/Function authorization. Admin-only and non-HTTP triggers cannot be imported this way.
Backend 401/403Inspect the backend credential reference and whether someone rotated or deleted the generated host key. Update the named value through the secret-management UI if necessary; do not hard-code it.
404Use the imported operation path shown by the Test tab, not a guessed /api route.
500 after adding policyConfirm subscription enforcement is enabled and the policy expression was copied without changing quote characters.
All calls return 429Wait a full renewal window and use a stable, intended subscription for the test.

Cleanup and References

Keep the imported API and Function App for the developer portal lab. Function hosting, storage, and monitoring can incur charges. If stopping, use the final cleanup and include every resource created during Function prework.

If the Function App is shared, do not delete it or rotate its keys. Remove only your imported API and coordinate removal of its APIM-specific host key with the owner.
