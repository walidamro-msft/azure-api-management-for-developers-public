Follow the Connected Path

Complete the labs in order using one disposable environment. The required path uses classic Developer APIM, a .NET 10 App Service backend, a prepared HTTP-triggered function, the APIM developer portal, and API Center Free.

Important: Azure resources incur charges. Do not use production data, shared groups, or credentials in source control. Keep resources until the dependent lab finishes, then follow final cleanup.

Complete the Prework

  1. Confirm an approved subscription, spending limits, resource-provider access, and allowed regions with your administrator. APIM, App Service, Functions/storage, and API Center must be permitted.
  2. Install Git, PowerShell 7, VS Code, .NET 10 SDK, and Azure CLI. Install the Azure Functions and C# extensions if preparing the C# function below.
  3. Clone the workshop repository and open it in VS Code:

  5. Prepare an email account you control for developer portal signup. Do not put personal details in shared screenshots.

Prepare the HTTP Function

Use the current C# Functions quickstart to create and deploy a minimal HTTP trigger. This is a separate app from the .NET 10 Catalog API; follow the Function runtime and SDK requirements in that quickstart rather than assuming the same target framework.

  1. Install the quickstart's required .NET SDK and Azure Functions Core Tools.
  2. In VS Code, run Azure Functions: Create New Project in a separate local folder.
  3. Choose C# and a supported .NET isolated runtime, then an HTTP trigger named Availability.
  4. Select Function authorization. Keep the generated template response; no business logic is required.
  5. Run the function locally as described in the quickstart and confirm an HTTP GET with ?name=Catalog returns 200.
  6. Create and deploy to func-apim-workshop-<suffix> using the quickstart's supported hosting plan in the workshop subscription. Place its Function App, storage, and monitoring resources in the dedicated workshop group wherever the creation flow allows.
  7. Test the deployed function with its authorized test workflow. Store any necessary credential only locally; record the expected 200 response, not the key-bearing URL.
  8. Record any supporting resources created outside the group so you can remove those exact workshop-owned resources later.

Expected result: Lab 03 can discover a deployed HTTP function with Function authorization in your subscription. If you already have an approved prepared function meeting those conditions, use it instead of creating another app.

Learn more: Function creation, runtime prerequisites, and deployment and APIM import constraints.

Readiness Check

  • APIM is ready on classic Developer tier.
  • The Catalog sample builds using .NET 10.
  • A deployed HTTP Function returns 200 and uses Function authorization.
  • You know which subscription and resource group each lab uses.
  • You can use an approved region and review plan costs before deploying.

Keep Secrets Local

APIM subscription keys and Function host keys are credentials. Do not add them to the repository, command history, screenshots, or API Center deployment URLs.
